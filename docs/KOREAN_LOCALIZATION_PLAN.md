# Wizardry VI DOS 한국어화 계획

작성일: 2026-08-31
브랜치: `korean-localization`

## 목표

`Wizardry VI: Bane of the Cosmic Forge` DOS판을 대상으로 한국어 텍스트 추출·번역·재삽입과 인게임 한글 출력을 구현한다.

이 저장소의 기존 역공학 자료는 최대한 보존하고, 한국어화 관련 변경은 `korean-localization` 브랜치에서 진행한다. `main`은 upstream(`martydill/Wizardry-6-reverse-engineering`) 추적용으로 유지한다.

## 현재 확인된 기반 자료

- `file_format_docs/MSG_DBS.md`: `MSG.DBS` 메시지와 `MSG.HDR`, `MISC.HDR` 기반 Huffman 구조 문서
- `file_format_docs/WFONT_EGA.md`: `WFONT*.EGA` 8x8 글꼴 구조 문서
- `loaders/`: 기존 메시지·그래픽·게임 데이터 파서
- `docs/`: 실행 데이터와 포맷에 대한 추가 역공학 기록

## Wizardry VII 작업에서 재사용할 것

- 한국어 용어집: 종족, 직업, 능력치, 스킬, 마법, 아이템 계열
- ASCII와 한글을 함께 쓰는 전용 2바이트 한글 인코딩 설계
- 8x8 계열 한글 글리프 자산과 글리프 매핑 방식
- 문자열 처리 시 바이트 길이와 논리 글자 수를 분리하는 원칙
- 원본 바이트 검증, 고정 크기 패치, 자동 테스트와 DOSBox 실기동 검증 방식

Wizardry VII의 실행 파일 주소나 오버레이 패치는 그대로 재사용하지 않는다. Wizardry VI의 코드 경로는 별도로 분석한다.

## 한국어 폰트 기준

한국어 글리프의 기본 서체는 **Galmuri7(갈무리7)** 로 정한다.

- 원본 `WFONT*.EGA` 셀은 8x8이므로 Galmuri7을 8x8 타깃 셀에 픽셀 정렬하여 래스터라이즈한다.
- 원본 WFONT는 128글자만 담을 수 있으므로 단순 폰트 파일 교체만으로는 한글 전체를 넣을 수 없다.
- Wizardry VII와 마찬가지로 2바이트 한글 코드 + 확장 글리프 저장소 + 문자 반복 루틴 수정 방식을 우선 검토한다.
- Galmuri는 SIL Open Font License 1.1을 따르며, 파생 글리프 데이터/도구의 라이선스와 reserved font name 조건을 지킨다.
- 현재 단계에서는 폰트 바이너리를 저장소에 넣지 않고, 추후 로컬 Galmuri7 입력을 받아 게임용 글리프 데이터를 생성하는 방식으로 구현한다.

세부 사항은 `korean/fonts/README.md`에 기록한다.

## 1차 기술 목표

### 1. 메시지 추출 및 왕복 검증

1. 기존 `MSG.DBS` 파서를 이용해 전체 메시지를 안정적으로 추출한다.
2. 메시지 ID, 제어코드, 원문을 손실 없이 CSV/JSON 등 편집 가능한 형식으로 내보낸다.
3. 수정하지 않은 원문을 다시 Huffman 압축하여 `MSG.DBS`와 관련 헤더를 재구축한다.
4. 원본과 기능적으로 동일한 데이터가 생성되는지 검증한다.

현재 전체 5,161개 개별 message ID 추출과 구조 검증은 완료했다. 원문 앞뒤 공백과 선행 0을 보존하는 lossless 추출기를 기준으로 한다.

### 2. 전체 사용자 노출 텍스트 인벤토리

1. `SCENARIO.DBS`의 고정 필드를 구조적으로 추출한다.
2. `WROOT.EXE` 및 OVR의 평문 문자열은 실제 참조(xref)를 확인한 뒤 번역 대상으로 승격한다.
3. `TITLEPAG.EGA`, `CREDITS.PIC` 등 이미지에 래스터라이즈된 텍스트를 별도 목록으로 관리한다.
4. 원본 바이너리/이미지는 GitHub에 올리지 않고 추출기와 구조 기록만 커밋한다.

현재 확인된 구조화 Scenario 항목은 아이템 452 + 몬스터 문자열 741 + NPC 이름 30 = **1,223개**다. `WROOT.EXE`에서는 실제 참조가 확인된 사용자 노출/진단 문자열 **12개**를 확정했다.

### 3. 폰트 출력 경로 분석

1. `WFONT*.EGA` 로더와 실제 문자 출력 루틴을 찾는다.
2. 시험용 글리프 한 글자를 바꿔 인게임에서 출력 경로를 확인한다.
3. 2바이트 한글 코드를 한 글자로 해석하는 디스패처를 설계한다.
4. 문자열 폭, 줄바꿈, 가운데 정렬, 입력 루프 등 1바이트 전제 코드를 조사한다.
5. Galmuri7 → 8x8 게임용 글리프 래스터라이저를 만든다.

### 4. 한국어 메시지 재삽입

1. 번역 문자열을 전용 한글 코드로 변환한다.
2. Huffman 트리와 메시지 인덱스를 한국어 데이터에 맞게 재구축한다.
3. 게임 제어코드가 원문과 동일하게 유지되는지 자동 검증한다.
4. 긴 문장과 메뉴 문구의 화면 폭을 검사한다.

## 우선 테스트 순서

1. 전체 메시지/Scenario/EXE/이미지 텍스트 인벤토리 완성
2. 원문 무수정 MSG round-trip 재삽입
3. `WFONT0.EGA` 시험 글리프 변경
4. Galmuri7 기반 8x8 한글 글리프 생성 테스트
5. 메뉴 한 단어 한글 출력
6. 짧은 메시지 한 문장 출력
7. 캐릭터 생성 UI
8. 본게임 대사와 전투 메시지
9. 제목/크레딧 이미지 패치 여부 결정

## 저장소 규칙

- 상용 게임의 원본 `EXE`, `DBS`, `HDR`, `EGA` 등은 Git에 커밋하지 않는다.
- 원본 게임에서 파생된 전체 바이너리 파일을 저장소에 올리지 않는다.
- 빌더, 패처, 차분 데이터, 테스트, 문서와 사용자가 직접 생성할 수 있는 산출물만 관리한다.
- MIT 라이선스인 upstream 코드의 라이선스와 저작권 고지를 유지한다.
- upstream 변경은 먼저 `main`에 동기화한 뒤 필요한 내용을 `korean-localization`으로 가져온다.
